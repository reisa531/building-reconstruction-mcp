# 完整流程与能力边界

数据采集/本地导入 → 坐标与单位检查 → 建筑分割 → 照片预处理与可选 SfM → 结构假设 → 构件及开口模型 → 规整几何 → 光照偏差估计和少量杂色 → MC 导出 → 预览与游戏验证。

## 本地 MCP 操作

- `capabilities()`：查看实现能力及可选依赖。
- `inspect_cloud(source)`：PLY/NPZ 点数、包围盒、来源及哈希。
- `start_job(operation, parameters)`：异步执行阶段，返回 job_id。
- `get_job(job_id)` / `list_jobs()`：读取运行状态与结果。
- `read_report(path)`：读取工作区内 JSON 报告。
- operations：`crop_cloud`、`symmetry_cloud`、`preprocess_photos`、`attempt_colmap`、`build_geometry`、`import_voxels`、`map_materials`、`validate_build`、`export_schem`、`preview_build`、`run_pipeline`。

所有路径相对于服务 `--root`；输入可用 root 内绝对路径；输出由服务建立独立任务目录。参数与例子见交付包 README 和 examples。管线从明确的构件模型或现有体素几何开始；前期照片、裁剪和点云对称阶段分别执行，产物路径显式传给后续阶段。

## 点云采集与裁剪

服务当前直接读取 PLY 与 NPZ。不自动镜像远程站点，不执行任意 shell，不包含通用 Potree 解码器。已有 CubeSHTech 下载和提取脚本仍是历史数据准备入口。

本项目 Potree 1.7 采用每点 16 字节：uint32 XYZ 与 RGBA。XYZ 乘 scale 并加节点最小角，子节点位置从八叉树路径计算，位 4/2/1 分别控制 XYZ 半区。该布局仅适用于已确认的当前数据，换 Potree 版本须检查元数据与编码。下载应保存节点清单与校验，支持续传；局部裁剪应先查节点包围盒，再解码相交节点，避免加载完整校园。

## 照片与 SfM

遮罩名跟随 COLMAP 输入图像文件名再加 `.png`，例如 `tower.png.png`。预处理不生成缺失杆件、不做 AI 关灯、不改变透视；灰度输入不承担最终颜色恢复。当前两张原照片的历史尝试没有成功模型，因此塔结构依赖实测点云与规则推断。

摄影测量成功时应检查相机注册、重投影误差、重复构件误匹配与独立留出照片，再计算照片坐标到点云坐标的相似变换。MCP 当前不提供自动 SfM→点云精配准或稠密重建，这些步骤需额外工具与显式验证。

## 对称、碎片和支撑

`symmetry_cloud` 的输入按 Y 向上解释，垂直轴旋转，不能将“中心对称”实现成含上下翻转的点反演。先通过实测重叠区评估候选对称轴与角度；低层入口和树木不应跟随塔身复制。补点保留 provenance=1 与 donor_index，不可作为颜色的实测证据。

当前通用工具不会自动搜索最优对称轴，也不会自动删除体素碎片或连接支撑。用 `validate_build` 的连通分量报告定位问题，再修改构件规格并重建；这保留开口和悬挑语义。支撑端点、直线截面、楼层间距可由 Agent 分析提出，但必须保存到可复现规格。

## 当前塔的两种复现

- `examples/tower-replay.json`：导入当前四边形平台几何，再按新默认参数映射实测颜色。复现几何与材质算法，不重新推断原始塔结构。
- `examples/tower-structure.json`：显式四边形平台与交叉支撑构件示例，可从参数重新生成。它是规则近似方案，不能宣称与历史 19,228 块完全相同。

旧版本的橙棕色校正是针对特定数据的外观处理，可能移除真实暖色；原始 RGB 必须保留。默认通用流程不自动做全局去暖色。
