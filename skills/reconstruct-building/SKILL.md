# 建筑重建

使用 `building-reconstruction` MCP。先读 `capabilities`，通过 `start_job` 启动阶段，用 `get_job` 等待实际完成并检查报告；大文件不经聊天上传。若工具尚未连接，读取本机交付包 `C:/BuildingWorkspace/reconstruction-kit/README.md`，使用其中本地启动方法。换机器时先定位交付包，不假定原路径仍存在。

## 决策与执行

1. **检查证据。** 确认点云格式、轴向、单位、建筑范围和 RGB 来源。调用 `inspect_cloud`，必要时 `crop_cloud`。原始数据只读，派生数据另存。Potree 原始节点须先按格式解码，不能当作 PLY 读取；相关方法见 [完整流程](references/workflow.md)。
2. **照片只提供可靠信息。** `preprocess_photos` 保留像素几何，输出灰度/CLAHE 图片及遮罩；原彩色照片留作外观参考。可选 `attempt_colmap`，以真实注册相机与三角化结果为准。失败记录 `no_model` 或失败原因；不能把两张对称照片等同于充分的摄影测量覆盖。
3. **建立中间模型。** 统一到 MC 的 Y 向上坐标，记录源到模型的 4×4 变换。先分析楼层、轴线、重复模数、杆件和对称假设，再写构件 JSON。当前工具根据明确参数建模，不会自动从任意照片识别整栋楼。测得、用户指定和推断结构必须区分。
4. **规则形状优先。** 使用 `box`、旋转矩形 `ring` 和 `rod` 表达墙、楼板、框、平台、梁柱与支撑。平面、厚度、间距、杆件截面统一；修复支撑时连到明确节点，不随意填实中空塔。对称关系先验证，再用于补全。模型 schema 见 [模型约定](references/model.md)。
5. **保留负空间。** 门窗、连廊、架空层、平台中孔都写为 openings，所有实体生成后统一扣除；玻璃按开口填充材质单独锁定。点云缺点不自动等于窗洞。细节见 [门窗规则](references/openings.md)。
6. **几何和材质分开。** 先 `build_geometry` 或 `import_voxels`，再 `map_materials`。仅使用 provenance=0 的实测点估色；限制同类构件的材质族，默认保留 25% 局部明暗残差和 15% 色度残差，亮度倍率限制 0.85–1.15，允许配置；根据画面效果调整，不宣称比例就是最终杂色方块占比。光照只做温和的方向偏差估计，不是物理反照率恢复。详见 [材质规则](references/materials.md)。
7. **验证后导出。** 检查开口、连通分量、尺寸、对称误差和材质阶段前后几何哈希。清理碎片须结合语义，不能把合法悬挑、栏杆或独立构件当作无意义碎片。生成 `.schem` 与预览，DataVersion 显式指定并匹配目标 Java 版；不能长期写死“最新”。实际游戏导入验证单独报告。

## 交付标准

给出 `.schem`、预览、构件 JSON / 输入配置、palette、任务记录与 SHA256，标注推断范围、颜色支持率、未验证项。复现需要同一输入、参数、依赖与工具版本；文件时间戳及任务 ID 可以不同。完整性不等于真实建筑测绘精度，也不代表结构工程安全。

塔示例保留 42×192×54 外包尺寸，平台为四边形，各层方向 0°/45° 交替；这属于本项目方案，不强加给其他建筑。楼房优先按楼层和开间建立立面，再布置门窗、窗框、玻璃及通行空间。
